## 账号与仓库条件

投稿需要有效本站账号、邮箱验证及相应平台绑定。支持 GitHub、Gitee 和 GitLab.com 的公开 Git 仓库。仓库必须直接归属于当前绑定的平台个人账号；组织成员身份、协作权限或提交记录不能替代直接归属核验。每个平台账号只能绑定一个本站账号，每个本站账号在同一平台只能保留一个绑定。

默认配额为 64 项保留投稿，实际以网站配置为准。公开、待处理、打回和历史状态均占用配额，主动移除后释放。Fork 可以收录并显示 Fork 及上游标记；归档仓库仅显示归档标记，不因归档失去收录或榜单资格。

## 许可证正文与策略来源

审核针对默认分支的当前提交。读取根目录下以 LICENSE、LICENCE、COPYING、UNLICENSE、COPYRIGHT 为基本名的普通文件，基本名大小写不限，可无后缀或以点、连字符、下划线连接后缀；也读取根目录大写 `LICENSES/` 中直接存放的普通文件。其他子目录、嵌套文件、符号链接、子模块、单独 NOTICE 或只写在 README 中的声明不作为许可证候选。

文件需要可解码为 UTF-8，不能含二进制 NUL。候选上限为 500 份，每份不超过 1 MiB，总计不超过 16 MiB。超限或不可读取的输入不会被当作通过。

分类依据是 [独立许可证策略仓库](https://github.com/He0xD4C0/njtech-oss-license-policy) 当前成功同步的完整正文，而非文件名、SPDX 标识或平台标签。白名单采用固定 SPDX 版本中标记为 OSI 已批准的许可证，并补充 CC0 公共领域授权；Unlicense 也在白名单内。黑名单包含明确选定的限制性许可证。具体范围见策略仓库及来源清单；未列入白名单不自动等于列入黑名单。

## 自动审核结果

- 全部有效候选正文被白名单完整覆盖，且其他条件仍满足：公开收录。
- 候选正文仅被黑名单完整覆盖：打回。
- 未找到候选许可证文件：打回。
- 未知、改写、不完整、无法解码、含额外条款或黑白名单混合：待处理。无论作者如何描述双重授权，网站均按实际读取的全部候选正文执行该规则。

网站可容忍部分格式变化及可完整识别的独立版权年份和持有人声明，但不忽略实质条款、金额、限制或未覆盖符号。标准模板占位信息、项目补充条款或不同正文版本仍可能需要补充策略，不能保证同一许可证名称的项目都自动通过。

“待处理”要求更正源文件或经审核更新策略后重新机审。管理员没有跳过机审手动放行的入口。已公开项目审核不再通过或明确失格时转为历史状态，保留此前公开快照；临时网络、平台或扫描故障本身不作为永久失格证据。

## 更新、撤回与归属变化

项目提交、策略更新、默认分支变化及平台资料同步都可能触发核验，展示不保证实时。你可以请求重新机审或移除投稿。转移后的仓库由新直接所有者认领时，旧归属记录转为历史。仓库改为私有或不再直接归属时，不再作为当前公开项目收录。

主动移除、解绑或注销会撤下相关公开投稿，并使其不再显示于公开历史榜单。内部证据、封存统计及备份的处理见隐私政策。

## 榜单口径

按 GitHub、Gitee、GitLab.com 分别计算，每个平台最多前十名。月份按 Asia/Shanghai 划分。月内 Star 增长使用实际观测或本次公开周期的发布基线计算，不虚构月初数据；并列时依次按期末 Star 数及平台仓库标识排序。

当月榜单随有效观测更新；已结束月份封存后不因后来失格而重新排名，主动撤回仍隐藏对应条目。历史榜单可能不足十项或出现名次空缺。榜单不构成代码质量、学术贡献、竞赛资格或官方评价的认定。
